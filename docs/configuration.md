# Danus — Configuration Reference

Deployment-specific values and secrets live in gitignored `config/*.env` files.
For an initial launch, repository wrappers use `scripts/env.sh` in this order:

```
config/dsh.env → config/danus.env → defaults for unset values
```

Managed children marked `DANUS_DSH_ISOLATED=1` bypass local env-file sourcing and
preserve their launcher's prepared explicit environment, including role/provider
and credential references passed to MCP. They must not reload a different route
from deployment files mid-launch. Legacy `runtime/runtime.env` is never sourced,
even on initial launch; explicit configuration and Pixi own the toolchain paths.

Copy the committed `*.env.example` templates without replacing existing secrets.
The Python toolchain comes from Pixi. Configuration of this repository does not
modify an already running DSH GUI or borrow its ambient provider/home settings.

## Explicit DSH provider and homes

| Variable | Meaning |
|---|---|
| `DANUS_DSH_BIN` | Explicit installed DSH executable used by repository launchers |
| `DANUS_DSH_PROVIDER` | Explicit provider identity; required, never guessed |
| `DANUS_DSH_PROVIDER_PATCH` | Absolute provider overlay JSON path; shell default is `runtime/dsh-provider.json` generated by setup |
| `DANUS_DSH_API` | Explicit provider protocol used when generating the overlay |
| `DANUS_DSH_API_BASE_URL` | Endpoint used by `scripts/setup-dsh.sh` when generating a provider overlay |
| `DANUS_DSH_REASONING_EFFORTS` | Comma-separated supported identity-mapped effort levels; include worker roster labels only if the route supports them |
| `DANUS_DSH_API_KEY` | Runtime credential; generated overlay refers to the env name, not the secret value |
| `DANUS_DSH_HOME` | Wrapper home override; default `runtime/dsh-home` |
| `DANUS_DSH_AGENTS_HOME` | Wrapper agents-home override; default `runtime/dsh-agents` |

Run `bash scripts/setup-dsh.sh` after filling the explicit route, or provide an
approved external overlay. `bin/dsh` is the isolated underlying wrapper;
`bin/danus-main` composes the main-role overlay, MCP and completed-turn plugin.
Its default is an isolated Web main with native goals/schedules/subagents;
`--headless` is an explicit one-shot alternative without the schedule service.
The main's checked-in wiring lives under `.dsh/`; its Web home persists under
`runtime/main-dsh/web/` to retain native goals/reminders. Headless main runs use
unique `runtime/main-dsh/` homes. Other headless role runs get fresh
isolated homes under `runtime/dsh-runs/`, so ambient GUI/session config cannot
silently change role access or provider routing. Keys stay out of argv and
snapshot contents.

`check-dsh.sh` performs offline/nonbillable configuration and MCP diagnostics.
It does not test live inference reachability. See [migration](dsh-migration.md)
for removal of legacy settings; no Codex configuration/auth/CLI fallback exists.

### Literature tools have separate dependencies

Changing the main model/provider route does **not** automatically configure generic
web search. In the pinned DSH base profile, `web_search` uses the separate
`deepseek-official` provider and requires its `DEEPSEEK_API_KEY`; an OpenAI-compatible
or local main-model route does not supply that credential. Only enable/configure
that dependency with operator approval; never silently select another provider.
An available tool name or a successful offline MCP check does not prove that live
search is usable.

`web_fetch` can retrieve accessible public pages without those search credentials.
The gateway's `search_arxiv_theorems` is a separate Matlas integration with its own
network/service availability. Roles expose only their configured retrieval tools.
If search is unavailable, report the limitation, use permitted sources that are
actually reachable, and leave unverified references flagged—never claim a lookup
succeeded or invent a citation.

### Per-project worker route (optional)

Set both values, with `<TOKEN>` the uppercase project name and non-alphanumeric
runs replaced by `_`:

- `DANUS_PROJECT_<TOKEN>_WORKER_DSH_PROVIDER`
- `DANUS_PROJECT_<TOKEN>_WORKER_DSH_PROVIDER_PATCH` (absolute JSON path)

Only that project's workers use the override. Main, verifier and renderers retain
their default explicit route. Partial pairs and legacy `_WORKER_API_*` profiles
fail closed; there is no silent fallback. Restart worker loops after changing
routing; mathematical continuity comes from persisted stores, not transcripts.

## Models and reasoning effort

Set supported values explicitly for the chosen route. Deployment setup requires
`DANUS_MAIN_MODEL` and `DANUS_MAIN_EFFORT`; do not assume old GPT model names or
`ultra` are supported just because upstream used them. Low-level inherited
fallbacks are not a recommendation or evidence of provider compatibility.

| Variable | Applies to |
|---|---|
| `DANUS_MAIN_MODEL` / `DANUS_MAIN_EFFORT` | Main and neutral defaults for services |
| `DANUS_WORKER_MODEL` | Workers; defaults to the neutral model |
| `DANUS_VERIFY_MODEL` / `DANUS_VERIFY_EFFORT` | Verifier overrides |
| `DANUS_WRITE_PAPER_MODEL` / `DANUS_WRITE_PAPER_EFFORT` | Paper renderer overrides |
| `DANUS_HUMAN_SUMMARY_MODEL` / `DANUS_HUMAN_SUMMARY_EFFORT` | Report renderer overrides |

Worker roster effort labels must also be supported by the selected route.
The verifier remains the correctness authority regardless of model choice.

## Ports and locations

| Variable | Default | Meaning |
|---|---|---|
| `DANUS_MAIN_PORT` | `8090` | Isolated DSH Web main, loopback only |
| `VERIFY_PORT` | `8091` | Verify service loopback port |
| `DASHBOARD_PORT` | `8099` | Read-only dashboard loopback port |
| `VERIFY_HOST` | `127.0.0.1` | Verify bind host; do not expose to untrusted networks |
| `DANUS_VERIFY_URL` | `http://127.0.0.1:8091/verify` | Gateway verification endpoint |
| `DANUS_RUNTIME` | `<repo>/runtime` | Ignored runtime tree |
| `DANUS_AGENTS_ROOT` | `runtime/projects` | Project worktrees |
| `VERIFIER_RESULTS_DIR` | `runtime/verify-runs` | Per-verification logs/results |
| `DANUS_PY` | `<repo>/.pixi/envs/default/bin/python` | Pixi-managed engine interpreter |

Ports and HTTP/MCP interfaces are coordinated boundaries; change both producer
and consumer if overriding them. See [architecture](../ARCHITECTURE.md).

## Worker pacing and checkpoints

| Variable | Default | Meaning |
|---|---|---|
| `DANUS_ROUND_HARD_TIMEOUT` | `14400` | Per-round wall-clock cap, seconds |
| `DANUS_MAX_ROUNDS` | `0` | Unlimited rounds; positive values are a backstop |
| `DANUS_MAX_CONSEC_FAILURES` | `5` | Exit after consecutive failed rounds |
| `DANUS_ROUND_BEAT` | `5` | Seconds between rounds |
| `DANUS_SNAPSHOT_AUTO` | enabled | `0` disables automatic full-turn/full-round snapshots, not manual capture |

Snapshots are best effort, not atomic across live writers. External Git metadata
is under `runtime/.gitstore/<project>.git`; raw DSH session logs are excluded.
See [Git recovery](git-resume.md) for restore constraints and inconsistent captures.

## Rendering and outward publication

| Variable | Default | Meaning |
|---|---|---|
| `DANUS_CHROME_BIN` | auto-detect | Chrome/Chromium for report PDFs |
| `TEX_ENGINE` | `pdflatex` | Paper TeX engine; also supports `xelatex`, `lualatex`, `tectonic` |
| `DANUS_WRITE_PAPER_RUN_LOG` | on | Per-call diagnostic logs (`0` disables) |
| `DANUS_PAPER_VERIFY_WHOLE_DOC_CAP` | `700000` | Character cap for whole-paper math verification; larger inputs return `too_large` |

Optional `config/latex-git.env` holds `LATEX_GIT_URL`, `LATEX_GIT_TOKEN`, and
`LATEX_GIT_AUTHOR_NAME` / `LATEX_GIT_AUTHOR_EMAIL`. Outward push/publication always
requires the operator's decision. See [operations](operations.md) and
[CLI/tools](cli-and-tools.md).
